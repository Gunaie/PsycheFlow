# 训练记录：三角色 LoRA 重训（dialog / report / triage，2026-09-27）

> 本文记录 18.3 阶段在云 GPU 上对 dialog、report、triage 三个角色分别微调的全过程。
> 前置历史见 [训练记录-2026-09-08.md](./训练记录-2026-09-08.md)（18.2 反模板重训）。

## 一、训练目标

在 18.2 数据备料（dialog 1386→2979、report 52→243、triage 0→1010）落地后，重训三角色 LoRA，验证本地私有化路线的效果上限。具体目标：

- **dialog**：扩大数据量后进一步抑制模板腔与封闭问句，提升多轮对话自然度
- **report**：用 243 条矩阵覆盖（5 档严重度 × 多量表）替代旧 52 条，提升报告发展建议的稳定性
- **triage**：首次训练意图分类 LoRA（5 类标签），替代纯云端推理，使本地可离线完成分诊

## 二、训练环境

| 项目 | 配置 |
|---|---|
| 云平台 | AutoDL，RTX 4090 24GB |
| 基座 | Qwen2.5-7B-Instruct |
| 微调框架 | LLaMA-Factory（QLoRA：4bit 量化基座 + LoRA） |
| 数据格式 | sharegpt，注入生产 system prompt（dialog/report/triage 三套） |
| 导出 | GGUF Q4_K_M，`import_gguf.ps1` 注册进本地 Ollama |

与 09-08 轮的关键区别：本轮是**三角色独立 LoRA**（非统一模型），report/triage 为首次在新数据上训练。

## 五、训练结果

| 角色 | 数据量 | 机时 | 最终 loss | 备注 |
|---|---|---|---|---|
| dialog | 2979 | 1h 44m | 1.187 | 5 epoch 收敛平稳 |
| report | 243 | 4m 43s | 1.834 | 数据量小，3 epoch 快速收敛 |
| triage | 1010 | 8m 54s | 0.041 | loss 异常偏低，疑似短输出（单词标签）导致背训练集；评测 40/43 未过拟合到不可用 |

> triage loss 0.041 偏低的原因：输出是单个标签词（寒暄/求助/倾诉/咨询/危机），上下文短（cutoff 1024），模型极易拟合。是否过拟合以 eval_triage 结果为准（见第六节）。

## 七、导出与导入

1. 云训练产出 LoRA adapter → 合并基座 → 导出 GGUF Q4_K_M
2. 下载到宿主机 `E:\OllamaModels\gguf\`：
   - `qwen2.5-dialog-lora-q4_k_m.gguf`
   - `qwen2.5-report-lora-q4_k_m.gguf`
   - `qwen2.5-triage-lora-q4_k_m.gguf`
3. 执行 `backend/scripts/finetune/import_gguf.ps1` 注册进 Ollama
4. `.env` 配置：
   ```
   LOCAL_MODEL_DIALOG=qwen2.5:dialog-lora
   LOCAL_MODEL_REPORT=qwen2.5:report-lora
   LOCAL_MODEL_TRIAGE=qwen2.5:triage-lora
   ```
5. `docker compose up -d backend` 重建后端生效

## 八、结论与遗留

- report 100% 通过，triage 危机 100%、整体 93.0% 有条件通过，dialog 经盲评复测（6/6 预热样本）质量达标。
- **triage 误判集中在「求助↔咨询/倾诉」边界**：idx16 把含「帮帮我」的求助判为倾诉，idx29/40 把咨询类边界问题判为求助。后续若补数据，应增加这两类边界样本。
- triage loss 异常低（0.041）需关注：若后续扩数据后 eval 下降，说明当前模型在背训练集。
- 与 09-08 轮相比，dialog 数据量 1386→2979（+115%），report 52→243（+367%），triage 从无到有 1010 条；本地三 LoRA + bge-m3-cpu 已可完全离线运行。
