## 1. 两套版本概述

| 对比项 | 版本一：云端 API 版 | 版本二：本地私有化版 |
|--------|-------------------|-------------------|
| LLM 来源 | 阿里云百炼（qwen3.8 / deepseek-v4） | 本地 Ollama（qwen2.5:7b） |
| Embedding | 百炼 text-embedding-v3 | 本地 bge-m3 |
| ASR/TTS | 百炼 qwen-audio | 本地 faster-whisper + edge-tts |
| 数据是否出本地 | ❌ 对话/测评数据上传百炼 | ✅ 全部数据留本地 |
| 成本 | 按量付费（约几十~几百元/月） | 0 元（已有硬件） |
| 效果 | ⭐⭐⭐⭐⭐ 稳定 | ⭐⭐⭐⭐ 接近云端 |
| 部署难度 | 0（现有即云端版） | 需配置 Ollama + 改 3 个文件 |
| 适用场景 | 有网络、追求稳定效果 | 内网部署、数据合规、离线使用 |

**核心设计**：两套版本共用**同一套代码**，通过 `.env` 中的 `LLM_MODE` 环境变量切换，无需维护两套代码。

## 2. 版本一：云端 API 版（零改动，即用）

项目当前就是云端 API 版，**无需任何代码改动**，只需确保 `.env` 配置正确。

### 2.1 配置 `.env`

```ini
# ============ 阿里云百炼平台 ============
DASHSCOPE_API_KEY=你的百炼API_KEY
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# ============ 模型配置（百炼模型） ============
MODEL_INTAKE=qwen3.8-2.4t-a95b
MODEL_TRIAGE=qwen3.8-27b
MODEL_DIALOG=deepseek-v4-pro-0813
MODEL_DIALOG_STREAM=qwen3.8-max
MODEL_REPORT=deepseek-v4-flash-0731
MODEL_EMBED=text-embedding-v3
MODEL_ASR=qwen-audio-3.0-asr-flash
MODEL_TTS=qwen-audio-3.0-tts-flash
TTS_VOICE=longanhuan_v3.6

# ============ LLM 模式（关键） ============
LLM_MODE=cloud

# ============ Ollama 本地兜底（可选，云失败时降级） ============
# 留空 = 禁用兜底；配置后云失败自动转本地
OLLAMA_BASE_URL=
OLLAMA_MODEL=qwen2.5:7b
```

### 2.2 启动服务

```bash

```

### 2.3 验证

```bash

http://localhost:5174
```

完成测评 → 对话 → 生成报告，全链路走百炼 API。

## 3. 版本二：本地私有化部署版（完全离线）

> 目标：所有 AI 能力（LLM/Embedding/ASR/TTS）全部本地运行，用户数据不出本机。
>
> 本地版分两个子版本：
> - **3.A 本地基座模型版**：直接用开源基座模型（qwen2.5:7b），不微调，**0 成本**
> - **3.B 云GPU微调版**：用云GPU微调模型后下载到本地运行，效果更好，**低成本**（约 10-30 元）

### 3.0 硬件需求确认（两个子版本共用）

|------|---------|-------------------|---------|
| GPU 显存 | 6 GB | 8 GB | ✅ |
| 内存（RAM） | 16 GB | 需确认 | ⚠️ 建议 ≥16GB |
| 磁盘空间 | 30 GB SSD | 需确认 | ⚠️ 建议 ≥50GB |

## 3.A 本地基座模型版（不微调，0 成本）

> 直接用开源基座模型 qwen2.5:7b，不做任何微调。适合快速验证、对效果要求不极致的场景。
> 成本：0 元 | 耗时：1-2 小时

> ✅ **已实施并验证通过（2026-09-06，RTX 4060 Laptop 8GB）**
> 实测结果：triage 意图分诊 **40/43 = 93.0%**（云端基线 97.7%；**危机类 8/8 = 100% 安全红线保住**，3 个误判均为求助/咨询边界样本且不改变路由）；报告合规 **76/76 = 100%**（发展建议 733-874 字、PDF 136-170KB）；正常对话热态首 token ~0.8s、危机路径 0.15s。
> **实施与文档的两处偏差（以实际为准）**：
> 1. Ollama 容器需加 `-e OLLAMA_KEEP_ALIVE=-1` 让模型常驻显存，否则闲置 5 分钟后首次对话有 ~40s 冷加载（qwen2.5:7b 4.7GB + bge-m3 1.2GB = 5.9GB，8GB 显存可常驻）；
> 2. 切换模式后**必须重建 RAG 索引**：`rag_store.reset_namespace()` 删旧 collection 再 `build_index()`（embedding 模型切换后旧向量语义空间不兼容）。
> 代码改动：config.py（llm_mode/local_model/local_embed_model + 校验）、llm.py（is_local + chat/stream/embed local 分支，直走 Ollama 不回退云端）、.env.example、test_llm.py（+11 例）。ASR/TTS 本地化推后（当前 local 模式语音仍走百炼）。

### 3.A.3 步骤 3：修改 `llm.py` provider 路由

打开 `backend/app/core/llm.py`，做以下 4 处修改：

#### 修改 1：`client` 属性

```python
@property
def client(self) -> AsyncOpenAI:
    if self._settings.llm_mode == "local":
        # 纯本地：主路径直走 Ollama
        if self._ollama_client is None:
            self._ollama_client = AsyncOpenAI(
                base_url=self._settings.ollama_base_url,
                api_key="ollama",  # Ollama 不校验 key
            )
        return self._ollama_client

    # cloud / hybrid：优先百炼
    if self._client is None:
        self._client = AsyncOpenAI(
            base_url=self._settings.dashscope_base_url,
            api_key=self._settings.dashscope_api_key,
        )
    return self._client
```

#### 修改 2：`model_for` 方法

```python
def model_for(self, role: str) -> str:
    if self._settings.llm_mode == "local":
        return self._settings.local_model_for(role)
    # cloud / hybrid：百炼模型名
    return {
        "intake": self._settings.model_intake,
        "triage": self._settings.model_triage,
        "dialog": self._settings.model_dialog,
        "dialog_stream": self._settings.model_dialog_stream,
        "report": self._settings.model_report,
    }.get(role, self._settings.model_report)
```

#### 修改 3：`chat` 方法（local 模式不走兜底）

```python
async def chat(self, role, messages, **kw):
    if self._settings.llm_mode == "local":
        # 纯本地：一次调用，失败即抛
        return await self._chat_once(self.client, self.model_for(role),
                                     role, messages, **kw)
    # cloud / hybrid：先 cloud，失败转 ollama（现有兜底逻辑）
    try:
        return await self._chat_once(self.client, self.model_for(role),
                                     role, messages, **kw)
    except Exception as e:
        if not self._settings.ollama_base_url:
            raise
        logger.warning(f"cloud chat failed, fallback to ollama: {e}")
        return await self._chat_once(self.ollama_client,
                                     self._settings.ollama_model,
                                     role, messages, **kw)
```

> `_chat_once` 是抽取出的单次调用函数（把原 chat 内联逻辑抽出来复用）。

#### 修改 4：`embed` 方法（Embedding 本地化）

```python
async def embed(self, texts: list[str]) -> list[list[float]]:
    if not texts:
        return []

    # local / hybrid：用 Ollama bge-m3
    if self._settings.llm_mode in ("local", "hybrid") and self._settings.ollama_base_url:
        try:
            resp = await self.ollama_client.embeddings.create(
                model=self._settings.local_model_for("embed"),
                input=texts,
            )
            return [d.embedding for d in resp.data]
        except Exception as e:
            if self._settings.llm_mode == "local":
                raise
            logger.warning(f"ollama embed failed, fallback to cloud: {e}")

    # 云端百炼（现有逻辑）
    return await self._embed_cloud(texts)
```

```python
_model = None

def _get_model():
    global _model
    if _model is None:
        # 8GB 显存建议用 CPU 模式（GPU 留给 LLM）
        _model = WhisperModel("large-v3", device="cpu", compute_type="int8")

async def transcribe(audio_path: str) -> str:
    segments, _ = _get_model().transcribe(audio_path, language="zh")
    return "".join(seg.text for seg in segments)
```

```python
import edge_tts

async def synthesize(text: str, voice: str = "zh-CN-XiaoxiaoNeural") -> bytes:
    communicate = edge_tts.Communicate(text, voice)
    audio = b""
    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            audio += chunk["data"]
    return audio
```

## 3.B 云GPU微调版（训练后下载到本地）

> 在云GPU服务器上用公开数据集微调模型，训练完成后把模型权重下载到本地 4060 运行。
> 成本：约 10-30 元（云GPU按时计费） | 耗时：2-4 小时（含训练）
> 效果：比基座版提升明显（triage 准确率 +5-10%，对话更贴合校园场景）

> 🟡 **训练包已就绪，待租云 GPU 执行（2026-09-06）**
> 代码侧已完成：config/llm 支持 local 模式按角色分模型（`LOCAL_MODEL_DIALOG`/`LOCAL_MODEL_REPORT`，留空回退基座，单测覆盖）；
> 训练包在 `backend/scripts/finetune/`：`cloud_train.sh`（云上一键：装 LLaMA-Factory→下 DeepWell→QLoRA 训 dialog/report→合并→转 Q4_K_M GGUF）、
> `convert_deepwell.py`、`dataset_info.json`、`train_dialog.yaml`、`train_report.yaml`、`import_gguf.ps1`（本地导入）。
> **与下文初稿的三处落地修正（以本节为准）**：
> 1. 微调数据目录是**项目根 `data/finetune/`**（容器内 `/app/data/finetune/`，与 DB/knowledge 同一挂载点），不是 `backend/data/finetune/`；
> 2. 训练后在云上**合并 LoRA 并导出 Q4_K_M GGUF**（单文件 ~4.7GB），下载 GGUF 回本地 `ollama create FROM xxx.gguf`；**不使用** Ollama `ADAPTER`（LLaMA-Factory 产出 safetensors，Ollama ADAPTER 要 GGUF，直接挂不可靠）；
> 3. `.env` 变量名是 `LOCAL_MODEL_DIALOG`/`LOCAL_MODEL_REPORT`（不是初稿的 `OLLAMA_MODEL_DIALOG`）。

### 3.B.3 步骤 2：租用云GPU并上传训练包

以 AutoDL 为例：

2. 实例启动后，用 AutoDL 提供的 JupyterLab（网页终端）或 SSH 连接
3. 把训练包上传到云上 `/root/ft/`：

   - 本地导出的 `data/finetune/finetune_report.jsonl` → `/root/ft/data/finetune_report.jsonl`
   - AutoDL 的 JupyterLab 文件管理器可直接拖拽上传；或用 scp：
     ```powershell
     scp -P 端口号 -r e:\Trae\PsycheFlow\backend\scripts\finetune\* root@实例IP:/root/ft/
     scp -P 端口号 e:\Trae\PsycheFlow\data\finetune\finetune_report.jsonl root@实例IP:/root/ft/data/
     ```

### 3.B.4 步骤 3：在云GPU上一键微调 + 导出 GGUF

训练包已把「装环境 → 下 DeepWell → 转换 → QLoRA 训 dialog/report → 合并 LoRA → 转 Q4_K_M GGUF」全部串好。在云实例终端执行：

```bash
cd /root/ft
bash cloud_train.sh
```

脚本要点（细节见 `backend/scripts/finetune/cloud_train.sh`）：
- `pip install llamafactory`，`HF_ENDPOINT=https://hf-mirror.com` 加速下载 Qwen2.5-7B-Instruct
- `git clone DeepWell-Adolescent` → `convert_deepwell.py` 生成 `/root/ft/data/deepwell_dialog.jsonl`
- QLoRA（4bit，lora_rank=16）：dialog 用 `train_dialog.yaml`（~2000 条 ×3 epoch，约 1-2h）；
  report 用 `train_report.yaml`（~50 条 ×3 epoch，约 20-40min；若未上传 finetune_report.jsonl 自动跳过）
- `llamafactory-cli export` 把 LoRA 合并进基座导出完整 HF 模型，再用 llama.cpp `convert_hf_to_gguf.py --outtype q4_k_m` 量化
- 产出（**只下载这两个 GGUF**，每个约 4.7GB）：
  - `/root/ft/gguf/qwen2.5-dialog-lora-q4_k_m.gguf`
  - `/root/ft/gguf/qwen2.5-report-lora-q4_k_m.gguf`

> 为什么不在本地合并/转换：合并 LoRA + 转 GGUF 需加载全量 FP16 模型（~15GB 内存/显存），4060 8GB 吃紧；云 4090 24GB 一次做完，本地只收一个量化好的 GGUF，最稳。

### 3.B.5 步骤 4：下载 GGUF 到本地

## 6. 故障排查

### 6.1 Ollama 连接失败

```
Error: Connection refused http://host.docker.internal:11434
```

排查：
```bash
# 1. 确认 Ollama 容器在运行
docker ps --filter "name=ollama"

# 2. 确认 11434 端口可访问
docker exec psycheflow-backend curl http://host.docker.internal:11434/api/tags

# 3. 如果 host.docker.internal 不通，改用宿主机 IP
# Windows: ipconfig 找到 WSL 的 IP
# .env: OLLAMA_BASE_URL=http://172.x.x.x:11434/v1
```

### 6.2 GPU 未识别

```bash
# 确认 GPU 可见
docker exec ollama nvidia-smi -L
```

如果看不到卡：
- Docker Desktop → Settings → Resources → 勾选 GPU
- 确认 NVIDIA 驱动版本 ≥555

### 6.3 显存 OOM

```
Error: CUDA out of memory
```

解决：
- 减小 `num_ctx`：在 Modelfile 中 `PARAMETER num_ctx 4096`
- 关闭其他占显存的程序
- 用更小的模型（qwen2.5:3b）

### 6.4 模型返回空内容

```
content="" finish_reason="length"
```

解决：
- 增大 `max_tokens`（report 角色建议 6000+）
- 或换可关思考链的模型

### 6.5 RAG 检索不相关

- 确认已重建向量库（3.A.6 步骤）
- `docker exec ollama ollama list` 确认 bge-m3 已加载

### 6.6 LoRA 合并失败

```
Error: ADAPTER file not found
```

解决：
- 确认 LoRA 权重路径正确（Modelfile 里的路径是容器内路径 `/root/.ollama/...`）
- 确认 LoRA 文件夹含 `adapter_model.bin` 或 `adapter_model.safetensors`
