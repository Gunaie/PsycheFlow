## 一、30 秒电梯版（最关键，先背这个）

PsycheFlow 是面向中小学生的心理筛查辅助系统，用 LangGraph 编排四个智能体做分诊、测评、干预、危机转介。核心设计是**安全前置**——危机检测用硬编码词表在所有 LLM 调用之前执行，不依赖模型概率判断。部署上支持云端百炼 API 和本地 Ollama 私有化两种模式，一套代码通过 `.env` 的 `LLM_MODE` 切换。

---

## 二、一句话架构口述

整个系统分三层：前端是 React 三态门户，学生教师零交叉；后端是 FastAPI + LangGraph，对话走 `triage → assessment → intervention` 一条链，危机直接走 `escalation` 短路；数据层是 SQLite + Chroma 向量库。LLM 有三级降级：百炼云端 → Ollama 本地 → 节点硬编码兜底。

  │

  └──(其余)──→ assessment → intervention → END

## 四、9 个高频 Q&A（每题 30 秒内答完）

### Q1：为什么用 LangGraph，不自己写 if-else？

对话链是有状态、有条件分支的——分诊后要根据意图分流，危机转介、寒暄直达、其余进测评干预。LangGraph 的状态图天然表达这种 DAG，加节点只需要 `add_node` + `add_edge`，不碰已有逻辑。代码在 `graph.py`。

### Q2：危机检测为什么要零 LLM 硬编码？

心理危机是高风险场景，不能依赖 LLM 的概率性判断，漏判代价太大。所以 `detect_crisis_with_words` 用关键词词表在**所有 LLM 调用之前**执行，命中直接走 escalation 节点，输出硬编码的 12355 青少年热线话术，同时写 `crisis_*.json` 和审计日志 DB 双写留痕。代码在 `safety.py` L16-L28（词表与扫描）+ `triage.py` L254-L272（短路）。

### Q3：双版本部署怎么实现？

一个开关：`.env` 里的 `LLM_MODE`。`cloud` 走阿里云百炼 8 个模型按角色分配；`local` 全走 Ollama，数据不出本机可离线。同一套代码，通过 `config.py` 里的 `local_model_dialog`、`local_model_report` 选模型，本地还能挂自己微调的 LoRA 合并 GGUF。

### Q4：RAG 怎么避免非危机用户推到危机热线？

两个机制。第一是**场景标签过滤**：每个知识文件有 `适用场景：` 元数据行，比如 `危机`、`焦虑`、`放松`，入库时存到 Chroma metadata，非危机查询直接排除带 `危机` 标签的片段。第二是**自适应阈值 + BM25 融合**：云端 text-embedding-v3 阈值 0.75，本地 bge-m3 阈值 0.95（bge-m3 输出归一化向量，L2 距离分布不同），BM25 独有命中给虚拟距离 = 阈值 − 0.03。改完知识库必须 `POST /api/rag/build` 重建索引。

### Q5：对话温度为什么设 0.6？

实测调出来的。本地 LoRA 模型在 0.35 温度下会复读上一轮用户的问句，就是模板腔，升到 0.6 后自然度改善。但不是越高越好——intake 用 0.1 要确定性，报告用 0.1 要结构稳定，不同角色温度不同，都在 `config.py`。质检不合格重试走三级阶梯：hint 0.6（点名禁令）→ rag_refresh 0.7（换 RAG 片段）→ context_trim 0.7（剔除历史 assistant）。

### Q6：你说的反模板具体怎么做的？

四层约束。第一层 Prompt：`SAFETY_BASELINE` 里硬规则，禁止闭合问句、整轮最多一个问题、禁止复读上轮建议、禁止幻觉归因、做法多样性。第二层质检：`check_reply_quality()` 函数检查生成结果，不合格走三级重试阶梯（hint 点名禁令 → rag_refresh 换 RAG 片段 → context_trim 剔除历史 assistant）。第三层微调：dialog 重训了 2979 条反模板语料，导出 Q4_K_M GGUF 导入 Ollama。回归用 `scripts/dialog_smoke.py`（单轮）+ `scripts/eval/eval_multiturn.py`（多轮 4 场景×4 轮，94% 通过率）。

### Q7：量表计分为什么不交给 LLM？

因为计分是确定性规则，LLM 算分可能出错还不可复现。PHQ-A、SCARED、SDQ、MHT 都在 `backend/app/scales/` 下用 Python 规则实现，SDQ 有反向计分题，PHQ-A 第 9 题自杀意念单项直达升级。LLM 只负责把分数字段转成自然语言的发展建议。

### Q8：数据安全怎么保证？

三层。SQLite 文件权限 0600，只有属主能读写。备份加密用 `scripts/backup_db.py`，先 `sqlite3.backup()` 在线拷贝到临时文件，再 `openssl enc -aes-256-cbc` 加密成 `.db.enc`，删明文临时文件。生产环境用非 root 容器，uid 1000 运行，数据目录 `chown 1000:1000`。

### Q9：云端 API 挂了怎么办？

三级降级链。百炼云端异常或返回空回复，`llm.py` 的 `chat()` 捕获异常自动转本地 Ollama；本地也没配或失败，就走节点级硬编码兜底话术。流式 `stream()` 只在还没 yield 任何 token 时才切换，避免半截回复。

## 六、5 分钟演示话术

**开场（30 秒）**：各位老师好，我演示的是 PsycheFlow 智能心理评估系统，面向中小学生校园筛查场景。我从学生作答、AI 对话、危机处理、教师后台四个环节走一遍。

**环节 1：门户与登录（30 秒）**
这是三态门户，学生教师零交叉。学生登录后进入首页，可以做量表、对话、看历史。

**环节 2：量表测评与报告（90 秒）**
我选 PHQ-A 抑郁量表，做完提交。系统用规则引擎计分，不交给 LLM，保证确定性。报告对齐 MHT 六章节结构，有子维度雷达图、测评用时、LLM 生成的发展建议，支持 PDF 导出。

**环节 3：AI 对话（90 秒）**
这是对话界面。我输入"怎么缓解焦虑"——注意这里有个设计点，系统用硬编码正则识别方法问句，把意图从"求助"纠偏为"咨询"，这样 RAG 才会检索缓解方法的知识片段，否则会被 RAG-skip 误伤。回复带可折叠的知识来源卡片，默认不展开，避免干扰阅读。

每轮回复都过一道确定性质检——检测到闭合问句或复读会自动走三级重试阶梯（点名禁令 → 换 RAG 片段 → 剔除历史），不合格的话术到不了用户面前。

**环节 4：危机处理（60 秒）**
我输入"我不想活了"。注意看，系统没有调 LLM，直接命中硬编码危机词表，秒级返回 12355 青少年热线话术，同时落盘审计。这是安全前置原则的体现。

**环节 5：教师后台（60 秒）**
教师端可以用 CSV 名单建批次，生成 6 位筛查码，学生匿名作答。批次详情页有危机名单和严重度分布，支持导出。

**收尾（30 秒）**：整个系统核心设计是安全前置和双版本部署，支持云端 API 和本地 Ollama 私有化切换，数据不出本机。我的演示完了，谢谢老师。
