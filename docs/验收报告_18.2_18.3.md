## 五、盲评验证结果

> **口径更正说明**：本节早前版本曾出现两种互相矛盾的记录——执行摘要/§5 写「1 成功 / 29 超时」（id7），HANDOVER 与数据详解写「4 成功 / 26 超时」。核对磁盘产物 `blind_eval_results.json` 与复测结果后，以本节为准统一更正。

### 5.1 执行记录

| 轮次 | 方式 | 结果 |
|------|------|------|
| 原始批量（2026-09-27） | 30 场景（vent_traj 12 / vc_traj 6 / consult 8 / help 4，10 主题），urllib 调本地 API，**60s timeout，未预热** | 磁盘产物 `blind_eval_results.json` 现状：**30/30 全部 fail（error 均为 timed out）** |
| 早先一次运行 | 同上脚本 | id7 曾以 55.9s 在 60s 内返回（唯一成功），产物后被全量重跑覆盖；「4 成功」无任何产物支撑，作废 |
| **预热复测（2026-09-27 晚）** | 先 1 次 warmup（56.1s），抽 id 7/3/13/21/25/29 共 6 场景，**180s timeout** | **6/6 全部成功**，产物 `blind_eval_warmcheck.json` |

### 5.2 超时根因

1. 首次请求触发 GGUF 冷加载到 GPU（模型文件 Q4_K_M 4.4GB，Ollama 列表显示 4.7GB），约 1 分钟；
2. 热态单轮生成实测 **55.9–97.2s/轮**（RTX 4060 Laptop，无历史的单轮），脚本 60s timeout 短于真实整轮时延 → 批量轮全部判超时，**非内容质量问题**；
3. 生产对话接口为 SSE 流式，首 token 后逐字返回，用户不需要等整轮；批量脚本后续应先预热并把 timeout 放宽到 ≥180s。

### 5.3 预热复测 6 样本质量

| ID | 类型 | 主题 | 字数 | 闭合问句 | 回复要点 |
|---|---|---|---|---|---|
| 7 | vc_traj | 创伤事件 | 101 | 无 | 正常化 + 纸笔写作宣泄 + 开放式提问 |
| 3 | consult | 恋爱情感 | 117 | 无 | 呼吸 4-6 + 「写下撕掉」情绪出口 + 开放提问 |
| 13 | vent_traj | 自我认同 | 45 | 无 | 共情反映 + 开放提问（未给具体方法，短于 50 字） |
| 21 | help | 情绪问题 | 94 | 无 | 辅导室预约/平台量表渠道引导，含「量表只是筛查不能替代诊断」边界提示 |
| 25 | vent_traj | 恋爱情感 | 37 | 无 | 纯共情反映（37 字，短于 50 字） |
| 29 | consult | 身体健康 | 76 | 无 | 呼吸 4-6 + 写纸 + 开放提问 |

**评估**：
- ✅ 6/6 无闭合问句、无空历史幻觉归因、收尾均为开放式提问；
- ✅ 做法多样（写作宣泄/呼吸/渠道引导/纯共情反映 4 类），无模板腔；
- ⚠ 「呼吸 4-6」出现于 2/6（id3、id29），方法集中度可接受但需持续监控（生产质检已有「跨轮同类做法重复」拦截）；
- ⚠ id13/id25 为 45/37 字，短于 prompt 期望的 50 字下限：生产 `check_reply_quality` 只卡 120 字上限、不卡下限，训练 QC 窗口为 25–120 字故不构成回归，但产品上可补一条下限软提示。

### 5.4 结论

盲评口径修正为：**原始批量 0/30（全部 60s 超时，技术原因）+ 预热复测 6/6 质量通过**。复测样本量仍小（6 条，自动断言+人工判读，非双盲评分），时延问题真实存在但由 SSE 流式缓解。
